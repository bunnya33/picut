# picut v0.5.17 · 连续滚动截屏

旧版每 80 毫秒采样，且连续三帧完全相同后才拼接，快速滚动中的中间帧被跳过。再加上最大匹配位移约为选区高度的 78%，停下来后容易已失去重叠。仅凭方向监听无法补回未采集的像素，因此本版同时修改了输入、采样、匹配和缓存。

## 现在的行为

- 连续采样，变化的画面也立即尝试拼接，不再等待停止。精确定时器目标间隔 16 毫秒；实际帧率取决于抓屏、窗口绘制、匹配、磁盘和系统调度，不承诺固定 60 fps。
- 只在滚动截屏会话期间观察选区内的滚轮，及原窗口在前台时的 Up/Down、PageUp/PageDown、Home/End。事件照常传递，不拦截滚动，不记录输入内容；关闭会话即撤销监听。Ctrl+滚轮不作为滚动方向。
- 输入后提前安排采样。方向用于区分上下滚动的候选，实际位移仍由像素确认，不把滚轮格数或按键次数当成固定像素距离。惯性导致实际方向与最新输入不同、但图像证据清晰时，采纳图像证据。
- 按行特征为位移投票，排除频繁重复的空白行，再验证重叠像素及上下边缘。保留必要的像素误差搜索回退。支持短重叠，大幅减少快速滚动或 PageDown 被旧位移上限拒绝的问题。
- 上下回看已截内容只更新当前位置，不重复追加。回到新内容后继续追加。仍按之前的规则判断上下边界，允许一侧固定、另一侧滚动；内部小窗口滚动仍不会直接拼接成长图。
- 短暂的重绘失败先尝试恢复，不立即停止自动滚动。持续无法对齐时暂停自动滚动，保留已截内容并提示返回已截位置；不会按方向猜出缺失内容。
- 自动模式在画面停止变化并且当前帧已对齐后继续发送一格滚轮。手动滚动会暂停自动模式。

## 性能与存储

临时条带改为未压缩的 RGB32 像素，避免每次追加都压缩 PNG。只缓存新增条带和小预览，不在每次滚动时重建完整长图；完成时再合成原图。像素没有降低质量。

临时文件占用比 PNG 大，上限仍受 6400 万像素及 10 万像素高度限制，原始条带总像素约不超过 256 MB，另有少量缩略图和文件系统开销。条带数量上限调整为 8192。正常取消或关闭会话时清理临时目录。内存中保留匹配帧、灰度参考及缩略图；不常驻完整长图。

1280×900 的合成文字测试图，40 次连续变化，每次滚动 127 像素：匹配、边界验证、缩略图和临时写入的中位耗时约 7.3 毫秒，P95 约 10.4 毫秒。此数字不含屏幕抓取和最终合成长图，不能直接换算成真实应用帧率。

## 边界

只要采样帧之间仍有可辨识重叠，就能持续对齐；如果一次跳过超过一屏、滚动条直接跳转、异步页面替换，或者内容完全重复导致无法判断距离，输入方向不能恢复没采集到的像素。本版会保留已有结果，无法可靠匹配时提示回到已截位置。Home/End 只提供方向提示，不保证跨越多屏的跳转可拼接。

目前从起始框选向下扩展，上滚用于回看已截部分，不向起始画面上方新增内容。
