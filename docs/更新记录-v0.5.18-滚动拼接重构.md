# picut v0.5.18 · 滚动拼接重构

上一版在用户实际使用中仍有较低的拼接成功率。本次先补充黑白正文、段落空白、局部动画与文字重绘测试，旧匹配器在前三类新增场景的第一步就拒绝了拼接。原先的彩色代码测试不能代表这些常见页面。

## 位移与补图

滚轮和上下按键提供方向、触发时机，无法直接给出跨软件一致的像素距离。实际位移由旧帧与新帧的重叠内容测量。窗口高度 300px，旧图顶部 100px 对上新图底部 100px，表示内容向下移动 200px，新图上方 200px 补入长图顶部。向下浏览时在底部补图。上下往返进入已截位置时不重复追加。

本版新增向起始位置上方扩展，使用原始像素条带，预览继续随长图增长缩放。

## 匹配修改

- 用局部二值特征为纵向位移投票，再根据有纹理的像素分块确认。局部动画、光标和固定侧栏不再使整行特征失效。
- 保留全部纵向像素行，只缩减匹配图宽度。原始截图像素仍用于最终图片，匹配图缩减不会降低导出分辨率。
- 小幅重绘色差允许容差，局部误差限制影响范围；重复正文中的不同数字仍参与接缝验证。无法区分距离的完全重复内容继续拒绝拼接。
- 边界验证把空白当成中性信息，修复正常段落留白被当成固定边框的问题。移动列中有明确固定头尾仍拒绝；允许一侧固定、另一侧滚动至上下边缘。
- 静止页面中的局部动画不再阻止自动模式继续滚动，不把动画当成新增条带。

## 抓帧与资源

在单显示器选区且 Windows 支持窗口排除捕获时，使用独立线程抓屏，复用 GDI DC、位图和像素缓冲。目标采样间隔 12ms，变化帧进入有限队列，GUI 匹配期间仍持续抓取。UI 消费队列的目标间隔 8ms。实际频率取决于系统抓屏和负载，并非固定帧率承诺。

队列最多 8 帧，以约 32MiB 作为目标容量，至少容纳 2 帧；超大选区可能超过这个目标。过载时保留两端帧，并合并采样最密集的位置，让待处理帧尽量均匀分布，减少中间重叠丢失。此队列只在滚动截屏期间存在，停止后释放。旧版 Win10 无排除捕获能力、跨显示器选区沿用原有 UI 隐藏与分屏抓取路径，目标间隔 16ms。

临时条带上限继续为 6400 万像素、10 万像素高、8192 条。正常关闭清理临时文件。无需新增 OCR、Python 或 OpenCV 运行依赖。

## 验证与实际范围

新增回归覆盖黑白中英文段落、空白边缘、局部动画、轻微重绘、带重复行的表格、平滑滚动的分数像素渲染，以及 300px 视口 / 100px 重叠向上补 200px 的例子。精确重复图像、无重叠跳转和固定上下框仍检查拒绝错误拼接。

真实 Windows 测试使用独立原生窗口线程连续渲染黑白正文，40 次滚动，每次 47px、目标间隔 20ms；工具 GUI 期间多次阻塞 90ms，抓帧线程继续采集，最终图片与原始测试图逐像素一致。另有实际 SendInput 滚轮、上方向键、PageDown、自动模式及停止检查。

最终完整回归 101 项通过、0 失败；2 项实桌面测试在离屏模式跳过，随后在 Windows 桌面单独验证通过（含初始化与清理共 4 项通过、0 跳过）。1280×900 合成图连续 40 次拼接，匹配、缩略图与条带写入中位约 8.1ms、P95 约 9.6ms；不含屏幕抓取与最终导出，不能换算为整体帧率或与微信直接比较。

这些是合成页面的离屏及实桌面验证，不代表微信的内部实现或所有网站的成功率。一次跳过整屏、缺少可辨识重叠、全屏连续动画或异步替换内容仍不能恢复未采集像素。无法确认时保留已截结果，提示返回已截位置。

报告位于 `.test-artifacts/native-v0.5.18-before.txt`、`native-v0.5.18-tests.txt` 和 `native-v0.5.18-scroll-windows-tests.txt`。

## 使用与回滚

安装包 `dist/picut-0.5.18-setup-x64.exe`；便携目录 `dist/picut-0.5.18/`。退出旧版托盘后启动新版。沿用原配置与历史路径。旧版程序和安装包保留，源码标签 `v0.5.17-continuous-scroll` 可回退；本次标签 `v0.5.18-scroll-matching`。
