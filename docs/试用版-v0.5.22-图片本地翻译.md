# picut v0.5.22 · 图片原位翻译试用

这是独立试用功能，尚未合入 `codex/picut-recording`。正式版 v0.5.21 的源码、安装包、便携包和数据目录保留。

## 使用

1. 先从托盘退出正在运行的原版，避免两个程序争抢 F1、F3 等全局热键。
2. 启动 `run-translation-trial.ps1`，或解压便携包后运行其中的 `picut.exe`。默认静默进入托盘。
3. 按 F1 框选截图，在文字识别旁点击“图片翻译”。贴图的右键菜单也有入口。
4. 默认自动判断中文／英文并译成简体中文。底部可以修改来源语言和目标语言；选择会保存在试用版自己的配置中。
5. 译文绘制在原文字区域内，保留图片尺寸、非文字内容和段落位置。点击“原文”可切换对照；“文字”展开只读文字面板，点击图片文字块可定位、选择对应文本。
6. 底部复制、保存输出当前显示的原图或译图。Esc 或取消返回截图／贴图。
7. F4 识别后可选中文字，在图片或文字面板右键选择“翻译选中文字（本地）”，复用识别结果，仅替换选中区域。

滚轮缩放图片，中键拖动，Ctrl+0 恢复适应窗口。文字面板内选中后 Ctrl+C 复制文字；图片区域 Ctrl+C 复制图片，Ctrl+S 保存图片。

## 模型与资源

运行时全部为 C++／Qt，无 Python 运行环境、独显、CUDA、NPU 或网络要求。首批包含 Helsinki-NLP OPUS-MT 英译中和中译英两个语言包，使用 CTranslate2 4.6.0、Ruy CPU 后端和 INT8 权重，SentencePiece 分词。来源、固定版本、转换说明和 SHA-256 在 `translation/models.json`，归属及许可证在 `licenses/translation/`。

OCR 结束后才启动翻译进程；翻译结束或取消后进程退出，释放模型。仅加载当前翻译方向，不在托盘启动时载入翻译模型。长段落显式分段，避免引擎默认截断输入。图片和文字不上传服务器。临时文字请求与结果目录在完成／取消后清理。

双向离线语言包合计约 165 MB（157.5 MiB）。英译中按上游模型要求加入 `>>cmn_Hans<<` 来源序列标记，选择简体中文。原生 CPU SDK 显式清理 CTranslate2 及 Ruy 的线程池，避免 Windows 退出时卡在 DLL 线程清理中；对应补丁在 `native/translation-sdk/windows-thread-cleanup.cmake`。

开发机转换模型需要构建专用 Python 环境，该环境不进入发布包。原生依赖由 `native/setup-translation-sdk.ps1` 准备；原始权重可用 `tools/download_translation_weights.py` 分块续传，校验后由 `tools/convert_translation_models.py` 转成 INT8。模型未随 Git 保存，完整试用包会包含离线语言包。

## 当前范围

- Windows 10 1809（17763）及以上 x64，与现有 Qt 6.8 版本的系统要求一致；ARM64、32 位系统及更早 Win10 版本未承诺支持。
- 首批只做中英互译，自动判断也是中／英两种。其余语言的 OCR 能力不代表已经具备对应翻译语言包。
- 优先针对网页、软件界面、文档等规则背景。文字周围采样背景色，去掉原文字后回填；复杂照片、渐变、旋转文字与文字框内装饰不保证无痕修复，未实现生成式背景修复。
- 译文根据原区域换行、缩小字号。若最小字号仍无法容纳完整译文，该区域保留原文并明确提示；完整译文可在文字面板复制。不会把被裁掉的半句当作完整译文输出。
- 翻译质量受原始 OCR、上下文、模型语言对影响。本试用不承诺与微信相同的模型、译文质量或速度。
- 4GB／双核是后续兼容性验证目标，尚不能用开发机实测代替低配真机与 Win10 验证。

## 本次实测

开发机为 Windows 11 x64、Ryzen 5 9500F（6 核 12 线程）、32 GB 内存，CPU 推理最多使用 4 个计算线程；以下是测试图片上的单次记录，包含进程与模型启动，不代表所有图片或低配设备表现。

| 图片／流程 | 耗时 | 临时工作进程峰值内存 |
| --- | --- | --- |
| 1000×650、7 行文字：OCR + 翻译 | OCR 约 0.5 秒，翻译约 0.8 秒 | 翻译约 142 MiB |
| 1920×1080、56 行、双栏编号列表：OCR → 翻译 → 回填 | 合计约 7.8 秒（OCR 约 3 秒、翻译约 4.8 秒） | OCR 约 308 MiB，翻译约 141 MiB |

OCR 与翻译进程依次运行，上表不是主程序常驻内存，也不是整个应用的峰值。完成后工作进程退出；同一图片再次打开可复用已有结果。全屏密集文字目前仍需数秒，尚未达到微信的秒出体验。

原有流程回归检查 115 项通过、3 项桌面专用用例跳过；翻译专项在 Windows 原生窗口平台完成 14 项检查，覆盖双向实际模型推理、简体短标签、数字保留、中文路径、语言包损坏报错、取消清理、段落／列表位置、只读面板、原文切换、缓存、实际 OCR 到图片导出。强制通用 CPU 路径也通过，但不代替老 CPU／Win10 真机验证。

便携包的 `translation-previews/` 包含测试原图、真实 OCR／翻译后的图片和耗时记录，可先查看布局效果。安装包提供独立名称和卸载项；未自动安装，也未替换现有程序。
