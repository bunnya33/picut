# picut v0.5.16 · F3 贴图修复

用户反馈：截图已复制，随后按 F3 偶尔贴不出来。当时没有热键和剪贴板读取日志，无法确定那一次的具体原因。本次修复了检查中发现、可由回归测试复现的两类问题。

## 修改

- 用 Shift+F3 隐藏全部贴图后，新建的贴图也会被隐藏。现在 F3 新贴图立即显示并置前，已有贴图继续隐藏，再次 Shift+F3 可恢复已有贴图。
- 剪贴板声明有图片但实际读取结果为空时，旧代码直接结束，且仍可能提示成功。现在先尝试有效的本地图片文件；仍未读到时，以 40、100、200、400 毫秒间隔最多重试四次，成功后立即停止。正常读取成功没有额外等待。
- Windows 剪贴板被占用时，先退出当前读取并定时重试，避免主动等待其他程序释放。实际 Qt/OLE 转换仍可能有系统等待，重试间隔不代表整个操作的耗时上限。
- 新的复制操作、后续 F3 请求、开始截图或进入设置，会取消此前的重试。读取失败不恢复无关的旧贴图；剪贴板确实为空时仍支持恢复最近关闭的贴图。
- 增加热键注册错误、收到全局贴图热键、剪贴板贴图请求和图片贴图成功/读取失败日志。不记录图片像素、复制的文字或文件路径。通知仍遵守原开关，默认关闭。
- 修正启动日志中的版本号。

截图选区内 F3 直接贴图、原位置贴图、录屏、OCR 和滚动截屏沿用原有功能。没有新增图片内存缓存。

## 验证

修复前的专项测试复现了隐藏状态和读取失败问题；修复后的专项测试覆盖普通图片、图片加文件格式、延迟读取、文件回退、持续读取失败、连续 F3、复制新内容取消旧请求及空剪贴板恢复关闭贴图。

完整原生回归：89 项通过、0 失败、1 项真实桌面滚动测试在离屏环境跳过。报告：`.test-artifacts/native-v0.5.16-tests.txt`。

Windows 平台合成图片贴图及异步落盘检查通过，五次首次绘制约 24～28 毫秒，保持原位置，保存历史未阻塞首次绘制。该检查直接使用合成图片，不经过系统剪贴板，不能等同于全局 F3 到读取剪贴板的耗时。

曾尝试用独立 Windows 窗口站隔离剪贴板进行真实占用测试，但系统拒绝该环境的剪贴板访问；这项实测没有通过。最终自动化用 Qt 离屏剪贴板验证恢复逻辑，不修改用户正在使用的系统剪贴板。仍需在正常桌面使用新版确认偶发问题是否消失。

如再出现问题，可查看 `%LOCALAPPDATA%\FloatShot\FloatShotNative-ImageTextTrial\logs\startup.log`，区分热键未注册、收到热键但读取失败、贴图已创建等情况。
