# picut v0.5.41：OCR 提速试用版

源码独立保存在 `codex/ocr-performance-trial`，主分支和 v0.5.40 的源码标签、安装包、便携目录均保留，待实际使用评价后决定是否合并。

## 行为

- 截图、贴图文字提取和图片翻译复用一个串行 OCR 服务与后台模型进程，各图片的识别结果仍独立显示。
- 图像通过每个请求独有的 Windows 共享内存传递，不再保存临时 PNG 或 JSON 识别结果。
- F1 截图界面出现 250 ms 后异步预热。截图界面提前关闭时不再启动预热；预热不阻塞截图显示。
- 完成后保留模型 30 秒；没有新请求则真正退出进程，释放模型与推理内存。主程序退出、取消当前请求或后台异常时会结束对应进程；下一次识别自动重建。
- 普通图片（不超过 400 万像素）的“自动”加速使用可复用的 CPU，避免重复 DirectML 初始化；更大的页面仍可自动尝试 GPU。保留手动 CPU / GPU 及自动 GPU 失败后的 CPU 回退。
- 保留现有 PP-OCRv6 small 模型、语言覆盖、方向分类、旋转文字和 CTC 字符位置。CPU 推理复用内存池与输入缓冲，并关闭线程空转。

## 验证

使用隔离数据和合成图片检查识别精度、字符几何、透明图片、旋转文字、连续请求、取消、后台崩溃恢复、空闲释放，以及 OCR 与图片翻译的集成。

性能对比使用同机、同图、同模型的 v0.5.40 CPU 单次进程与本版共享内存 CPU 服务，单独记录冷启动和连续热请求；不将不同机器的 LumaShot 测量值当作本版收益。

| 合成样本 | v0.5.40 单次 CPU | v0.5.41 首次 CPU | v0.5.41 连续三次 CPU |
| --- | ---: | ---: | ---: |
| 760 × 240，4 行 | 6.65 秒 | 9.41 秒 | 2.61–2.80 秒 |
| 1920 × 1080，20 行 | 12.65 秒 | 9.62 秒 | 2.60–4.31 秒 |
| 2560 × 1440，108 行、3 列 | 36.53 秒 | 39.10 秒 | 8.07–10.05 秒 |

每个样本连续三次结果与旧版的文字完全一致，并检查字符位置。旧版计时包括启动子进程、加载和识别，不包括提前保存输入 PNG 的时间；新版计时包括共享内存准备、排队、加载和识别。此处为 CPU 对 CPU 的对比，旧版“自动”加速可能使用 GPU，不能据此推断所有默认场景的收益。

本轮 OCR 测试 17 项通过，OCR 界面检查 7 项通过，覆盖截图和贴图中的待确认文字、选字复制、缓存、缩放、关闭及取消。图片翻译集成 5 项通过；依赖另外指定参考图的 2 项未执行。完整测试与性能原始记录在 `.test-artifacts/native-v0.5.41-*`。

## 试用时关注

- 连续识别已明显缩短等待；首次或空闲释放后的请求仍需加载模型，部分冷启动样本比旧版慢。F1 时提前加载旨在利用框选期间的时间，不能保证每次识别都已预热完成。
- 本版没有更换识别模型，也没有省略方向识别。密集长图仍需较长推理时间，尚不能承诺秒出。
- 模型复用以短时间保留内存换取响应速度。上述 CPU 样本的后台进程私有内存约 229–590 MB；空闲 30 秒后进程退出，内存释放。应用静默启动时不加载 OCR。

实现参考 LumaShot 的模型预热、进程复用和空闲释放思路，使用 picut 原有识别管线。参考源码版本：<https://github.com/jimmgreen/LumaShot/tree/ee4e30992356468459e3f69e487d4947c12a619a>。

## 使用与回退

安装包：`dist/picut-0.5.41-setup-x64.exe`；便携包：`dist/picut-0.5.41-win-x64.zip`。运行前先退出当前托盘实例。设置、历史和贴图沿用现有数据目录。

回退时退出 v0.5.41，再运行 `dist/picut-0.5.40/picut.exe`，或重新安装保留的 v0.5.40 安装包。
