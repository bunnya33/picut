# 浮光 FloatShot v0.5.4：PP-OCRv6 Small 试用版

文字检测和识别都切换为 **PP-OCRv6 small**。方向分类保留 PP-LCNet x1.0 服务端模型。识别窗口的语言组显示 Small，设置说明同步更新；最近使用的识别器、语言组和运算设备仍从已有设置读取。旧版 v0.5.3 完整模型包保留，可退出当前版本后分别运行作对照。

本版仍是 C++20 + Qt Widgets，模型在独立 C++ 进程离线运行。大图自动显卡加速、小图使用 CPU，显卡失败时自动回退 CPU。完成或取消后退出 OCR 子进程。没有 Python、服务器或常驻模型。

## 替换的模型

| 模型文件 | v0.5.3 medium | v0.5.4 small |
| --- | ---: | ---: |
| 文字检测 | 59.24 MiB | 9.47 MiB |
| 文字识别 | 73.08 MiB | 20.25 MiB |
| 文字方向分类 | 6.46 MiB | 6.46 MiB |
| 合计 | 138.78 MiB | 36.18 MiB |

表中是 ONNX 模型文件大小，不是运行内存。检测和识别都替换为官方 Small 档，保留原始精度，不量化、不修改字典输出索引。三个模型的固定下载源为 RapidAI/RapidOCR v3.10.0，下载及打包均校验 SHA-256，详见 `native/setup-ocr-sdk.ps1` 和包内 `ocr/models.json`。模型目录只包含当前版本的三个权重、字典和清单，不把 medium/tiny/mobile 实验权重混入发布包。

## 语言覆盖

Small 主识别器与 medium 的官方覆盖范围相同：中简繁、英文、日文及 46 种拉丁字母语言，共 50 种。没有加入韩文、阿拉伯文、西里尔文字、泰文和印度文字体系的专用识别器。“支持 50 种”不代表所有文字体系，也不代表本项目已完整验证全部语种。

官方来源：[PP-OCRv6 模型说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.md)。

## 同图性能和识别效果

测试电脑为 AMD Ryzen 5 9500F、AMD Radeon RX 580 2048SP，显存约 4 GB。采用同一张 2560×1440、3 列共 120 行、16 px 中英数字混排图片，同一 C++ 识别程序，检测参数、切块、方向分类和批次设置相同，仅替换检测/识别权重。GPU 每批最多 4 行，CPU 每批 1 行。每次均为新进程，计入模型加载、PNG 解码、检测与识别。

| 模型 / 设备 | 总耗时 | 120 行字符错误 | OCR 子进程峰值工作集 |
| --- | ---: | ---: | ---: |
| medium / CPU | 17.930 秒 | 0 / 4812 | 787.4 MiB |
| small / CPU | 5.480 秒 | 0 / 4812 | 384.4 MiB |
| medium / GPU | 4.913 秒 | 0 / 4812 | 353.6 MiB |
| small / GPU | 2.811 秒 | 0 / 4812 | 315.4 MiB |

GPU 的工作集不包含显存，不能据此计算总内存节省。表中是各配置一次同机测量，不是多次平均值，实际速度随负载、截图内容和设备变化。Small 在这张大图的 GPU 测量中约提速 1.75 倍，CPU 约 3.27 倍；仍不能承诺整屏秒出。

沿用 v0.5.3 的 8 张中英数字样本，12/16/24/36 px、浅色/深色背景，共 448 个非空白字符：Small CPU 和 GPU 均错 1 字，12 px 深色“截图”识别为“载图”。旧版 medium 在这组样本错 2 字，Windows OCR 错 49 字。这个小样本结果不代表 Small 的总体精度高于 medium。

繁体、日文、法德文、透明、90°/180°、多行样本在初测中无字符错误。越南文仍有 5 个字符错误，主要为变音符号，不能承诺各语种同样精度。错误计分只忽略空白，保留标点、大小写、简繁差异，不改写识别结果。

完整同图对照和各样本内容在包内 `comparison-report.json`；CPU/GPU 回归报告在 `quality-report.json`、`gpu-quality-report.json`、`dense-timing.json`、`dense-gpu-timing.json`。原始图片和实验结果位于 `.test-artifacts/native-v0.5.4-model-comparison/`、`.test-artifacts/native-v0.5.4-ocr/`。

## 验证和使用

原生回归 19 项、OCR 回归 11 项、录屏回归 10 项全部通过，没有跳过。覆盖中文/多语种样本、透明和旋转图片、大图分块、CPU/GPU 字符结果对照、实际显卡后端失败后的自动 CPU 回退、缺失组件、取消和识别窗口关闭。

最终回归中的 120 行图片，Small CPU 5.610 秒、GPU 3.034 秒；CPU/GPU 结果在忽略空白后相同，8 张中英核心样本仍为 1/448 字符错误。与上表初测之间存在正常波动，实际截图不能按固定秒数保证。

清除开发 SDK/Python 路径，在独立验证目录使用 Windows Qt 平台运行 8 项便携 OCR 检查全部通过；显卡运行库、CPU 回退和取消清理正常。验证运行库 QtTest 仅复制到独立目录，不进入发布包。发布主程序另做三次合成 OCR，实际返回模型均为 PP-OCRv6 small，主程序没有加载 ONNX Runtime，完成后没有残留识别子进程。

这次合成验证中，主程序工作集从约 25.4 MiB 到三次 OCR 后的 29.8 MiB；验证模式没有显示工作台、恢复用户贴图或录屏，不是日常启动内存的固定值。区域、全屏、第二屏的实际成片解码检查均通过，录屏控制条和边框对应像素没有进入视频，结果限于本机采集环境。

发布包打包时逐项核对 Small 权重校验值，不含 Python、QtTest、PDB 或其他档位的实验模型。便携包中的 Small 选择标签及识别结果窗口已检查。

运行 `dist/FloatShot-Native-0.5.4/FloatShotNative.exe`，或解压 `dist/FloatShot-Native-0.5.4-win-x64.zip`。请保留整个目录，尤其是 `ocr/`、`gpu/` 和运行库。先用旧版托盘菜单退出，以释放 F1/F3 等快捷键，再启动新版。旧版 v0.5.3 目录和 ZIP 保留。
