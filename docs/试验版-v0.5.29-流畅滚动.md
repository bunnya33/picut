# picut v0.5.29 长截图流畅性试验版

本版在独立分支 `codex/scroll-performance-trial` 上改进长截图，保留 v0.5.27 Astra 版和 v0.5.26 正式版。截图、标注、F3 贴图、录屏、OCR 和图片翻译继续沿用现有功能。

## 安装与试用

- 安装包：`dist/picut-0.5.29-scroll-trial-setup-x64.exe`。
- 便携包：`dist/picut-0.5.29-scroll-trial-win-x64.zip`，解压整个文件夹后启动 `picut.exe`。
- 开发目录入口：`run-scroll-performance-trial.ps1`，默认静默启动到托盘。
- 先从托盘退出旧版以释放 F1、F3 等热键，再启动本版。安装器不会主动结束旧版进程。
- 按 F1 选择区域，再点工具栏“滚动截屏”，在原窗口内滚动；预览随已确认内容延伸，完成后复制、保存或贴图。

本版使用独立的安装身份和数据目录：

| 项目 | 位置 |
| --- | --- |
| 默认安装目录 | `%LOCALAPPDATA%/Programs/picut-scroll-performance-trial` |
| 默认数据目录 | `%LOCALAPPDATA%/FloatShot/FloatShotNative-ScrollPerformanceTrial` |
| v0.5.27 安装目录 | `%LOCALAPPDATA%/Programs/picut-scroll-trial` |
| v0.5.27 数据目录 | `%LOCALAPPDATA%/FloatShot/FloatShotNative-ScrollV2Trial` |

不会自动迁移旧版设置和历史。回退时退出本版，从原有快捷方式或 `run-scroll-trial.ps1` 启动 v0.5.27 即可。正式版入口仍为 `run.ps1`。

## 本轮改动

1. 使用分散特征和稀疏光流提出滚动位移，再由原始像素验证；滚轮和上下键仅提供方向提示。
2. 分别识别局部变化区域，允许多个小加载圈、动态表情或悬停变色参与同一帧匹配。大范围动画、没有可靠坐标证据的重复内容仍会暂停追加。
3. 历史索引按行保存特征，限制候选数量，减少长图越长、匹配越慢的情况；外观相似但数字不同的重复行增加歧义检查。
4. 将桌面采集、匹配、临时缓存写入和界面预览分开处理。原图进入临时文件，后台写入；预览合并刷新，回访已截取区域只移动视口提示。
5. 缓存不保存整张长图的灰度副本，长图预览随高度降低分辨率。最终导出仍保留原始像素尺寸。
6. 仅在延伸时更新有限的接缝尾段，减少动态表情在接缝处由两个动画相位混合成图的情况。已经确认的远处内容不被新出现的相似图片覆盖。
7. 完成和取消异步收尾，缓存写入或安全上限触发时保留已确认结果并停止采集，用户仍可导出。

## 本机验证

测试日期：2026-10-24。机器为 Ryzen 5 9500F、32GB RAM、Windows 11 Pro 10.0.26200。以下是固定回放与受控桌面场景的结果，不能当作任意网页或应用的成功率。

### 同一 30000px 离线回放对比

1000×800 选区，每次移动 397px，77 次更新，最终高度 30800px。两个版本的静态最终结果均与原图逐像素一致。离线匹配计时不包含桌面采集和屏幕呈现。

| 指标 | v0.5.27 Astra 版 | v0.5.29 本版 |
| --- | ---: | ---: |
| 单帧接收处理 P95 | 143.132 ms | 10.134 ms |
| 单帧接收处理 P99 | 152.062 ms | 16.180 ms |
| 前段 / 后段 P95 | 40.252 / 152.062 ms | 10.103 / 10.568 ms |
| 进程工作集增量（含测试帧） | 41.10 MiB | 27.15 MiB |
| 成功接收 | 77 / 77 | 77 / 77 |

本版离线满速处理约使用 1.20 个逻辑核心，包含后台写盘。这不等于正常用户滚动时的占用，也未证明全链路始终低于一核。

记录：`.test-artifacts/native-v0.5.29-scroll-v2/long-tracking-budget.json` 和 `.test-artifacts/native-v0.5.29-baseline-results/long-tracking-budget.json`。

### 实际 Windows 桌面采集与预览

独立 Win32 源窗口持续滚动 40 次，三个场景的最终图片均逐像素一致，没有因中途拒绝的帧产生缺行。表格计时为“源窗口请求重绘 → 预览 Paint 事件开始”，包含桌面采集、匹配与界面调度，不含显示器实际呈现；资源占用包含测试用源窗口及图像。

| 场景 | 预览延迟 P95 / P99 | 平均逻辑核心占用 | 工作集增量 |
| --- | ---: | ---: | ---: |
| 正常事件循环，段落滚动 | 66.221 / 70.021 ms | 0.47 核 | 55.61 MiB |
| 故意阻塞界面 90ms，段落滚动 | 84.514 / 100.995 ms | 0.39 核 | 59.51 MiB |
| 故意阻塞界面 90ms，代码及滚动条 | 82.277 / 93.422 ms | 0.45 核 | 47.02 MiB |

另一轮相同桌面场景的工作集增量出现过 67.61 MiB，包含初始驱动开销等差异。因此不能声称完整桌面链路已在所有情况下低于 64 MiB。段落场景仍有重绘中间帧暂时拒绝，后续帧恢复后最终图完整；不声称每个采集帧都能匹配。

记录：`.test-artifacts/native-v0.5.29-scroll-ui-tests.txt` 及 `.test-artifacts/native-v0.5.29-scroll-ui/`。

### 回归范围

- 多个加载圈、快速跨步、静止动画不延伸、悬停卡片变色、重复正文的不同数字、分数像素滚动、动态接缝、真实三圈参考图、长图持续跟踪。
- 真实 DXGI 桌面采集、独立源窗口采集、手动滚轮和键盘方向、异步完成导出。
- 原有截图、标注、贴图与基础功能，以及 OCR 和翻译测试。

## 适用范围与限制

- 输出仍有安全上限：6400 万像素、100000px 高度、8192 个条带，任一先达到便停止追加。比如原图宽 1920px 时，像素上限对应约 33333px 高度；宽 3840px 时约 16666px。已截到的部分仍可导出。
- 采集待处理帧队列有 24 MiB、最多 8 帧和约 250ms 积压预算；临时文件写队列预算约 12 MiB。单帧本身超过队列预算时允许容纳该帧。触限会暂停并提示，避免悄悄跳过内容。
- 页面一次跳过所有重叠内容、全页相似重复、大片动画或窗口遮挡仍可能无法定位。本版保留拒绝有歧义帧的规则。
- 原始图像临时缓存会使用本机磁盘，随截图长度增长；普通完成或取消后由会话清理。最终导出的大图需要一次成图内存，不能以匹配阶段的工作集增量代替导出峰值。
- 不要求独立显卡或联网。运行时是原生 C++ / Qt，没有 Python；新增 OpenCV 的 core、imgproc、video 静态链接，只在长截图会话中初始化跟踪资源。
- 最低系统目标仍为 Windows 10 1809 x64；本轮仅在上述 Windows 11 机器实测，未进行 Windows 10 或旧笔记本实机验证。
- 设计文档中的单帧 P95≤8ms、P99≤16ms、完整链路额外内存≤64MiB 等是目标，尚未全部达到。本版交付用于对实际页面的流畅性、局部动态容错及最终完整性进行试用。
