# 浮光 FloatShot v0.5.2：离线完整 PaddleOCR

本版仍为 C++20 + Qt Widgets，不使用 Python。截图和贴图的“文字识别”默认改为 PaddleOCR。模型随便携包一起提供，无需连接服务器、上传图片或使用 API Key。“服务端档”只是模型规格，推理完全在本机 CPU 上运行。

## 使用

截图选区或贴图菜单 → 文字识别。在识别窗口可编辑、复制结果，切换 Windows OCR 作对照，调整文字方向后重新识别。设置 → 文字识别可修改默认识别器和文字语言组；最近选择会保存。

模型会自动纠正单行 180° 倒置文字，并把竖向裁切的文字行转为水平识别；整张图片方向不合适时，可选择顺时针/逆时针 90° 或 180°。这不是自动理解所有复杂竖排书籍的阅读顺序。

点击关闭或 Esc 会取消 PaddleOCR 并退出子进程。临时图片和结果在识别结束或取消时删除；主程序不加载 ONNX Runtime/OpenCV/模型。超时 3 分钟会停止识别。文字结果不做猜测数字、拼写纠正或语言模型润色。

## 模型和语言范围

主模型采用 **PP-OCRv6 medium**：这是 PP-OCRv6 最大档、面向服务端的完整模型，不使用 small/tiny/mobile 替代，不做量化或裁剪。文字方向使用 **PP-LCNet x1.0 服务端分类器**。原始精度 ONNX 模型由 RapidAI/RapidOCR v3.10.0 转换发布，下载路径和 SHA-256 校验见 `native/setup-ocr-sdk.ps1`、包内 `ocr/models.json`。三个模型合计约 138.8 MiB。

官方主模型支持 **50 种语言**：

- 简体中文、繁体中文、英文、日文。
- 法文、德文、意大利文、西班牙文、葡萄牙文、荷兰文、波兰文、罗马尼亚文、捷克文、瑞典文、挪威文、丹麦文、芬兰文、匈牙利文、土耳其文、越南文、印尼文、马来文、阿塞拜疆文、南非荷兰文、波斯尼亚文、克罗地亚文、威尔士文、爱沙尼亚文、爱尔兰文、冰岛文、库尔德文、立陶宛文、拉脱维亚文、马耳他文、毛利文、奥克文、斯洛伐克文、斯洛文尼亚文、阿尔巴尼亚文、斯瓦希里文、他加禄文、乌兹别克文、拉丁文、塞尔维亚文（拉丁）、加泰罗尼亚文、巴斯克文、加利西亚文、卢森堡文、罗曼什文、克丘亚文。

这是官方声明的覆盖范围，**不代表每种语言都经过本项目完整验证，也不代表支持全世界的文字体系**。本版没有加入韩文、阿拉伯文、西里尔文字、泰文、天城文字、泰米尔文、泰卢固文的专用识别器：官方这些专用模型仅有 mobile 档，先遵守“不用轻量模型”的要求。架构可扩展独立语言组，不能用主模型的高置信度输出假装支持这些文字。

来源：[PaddleOCR PP-OCRv6 官方说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.md)、[PaddleOCR 多语言模型说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.md)。

## 识别效果实测

在同一台 Windows 11、AMD Ryzen 5 9500F 电脑上，使用 CPU 推理，用 Microsoft YaHei UI 生成原始像素图片，两个引擎读取完全相同的图片。核心内容为：

> 中文截图识别测试，录屏已暂停。 FloatShot ABC abc 0123456789 100.50 2026-10-10

覆盖 12/16/24/36 px、浅色/深色背景，共 8 张、448 个非空白字符。字符错误率使用 Unicode 字符级编辑距离，只忽略空白，保留标点、大小写与简繁差异，不通过修改答案抬高准确率。

| 引擎 | 字符错误数 | 字符错误率 |
| --- | ---: | ---: |
| 原 Windows OCR（系统默认 zh-Hans-CN） | 49 / 448 | 10.94% |
| 完整 PaddleOCR | 2 / 448 | 0.45% |

两个剩余错误：12 px 深色样本“暂停”识别为“智停”；36 px 深色样本“别”识别为繁体“別”。繁体、日文、法德文样本以及透明背景、90°/180°、多行样本在本次样本中无字符错误。越南文样本仍有 5 个错误，主要漏掉变音符号，不能承诺所有语言相同精度。

这些是自生成样本的对照结果，不是大量真实截图上的总体准确率。模糊、压缩、极小文字、艺术字、复杂排版仍可能识别错误。真实使用时应检查金额、日期、帐号等关键结果。

完整逐项结果为包内 `quality-report.json`，生成图片、JSON 结果和识别窗口预览在 `.test-artifacts/native-v0.5.2-ocr/`。小图保留原始像素并适度放大检测，大图分块检测，合并重叠文字后用原始像素裁切识别，避免整体缩小造成小字损失。

## 耗时与内存

| 场景 | 实测 |
| --- | --- |
| 单张中文数字小图，冷启动到识别结束 | 约 0.45 秒；识别进程峰值约 251 MiB |
| 17 张样本共享同一次模型加载的测试批次 | 约 4.9 秒；批次识别进程峰值约 385 MiB |
| 3400 × 1850 px 跨分块边界图片 | 约 5 秒；识别进程峰值约 870 MiB |
| 原生主程序内存验证起始阶段 | 工作集约 25.3 MiB |
| 连续识别 3 次后的主进程 | 工作集约 29 MiB；ONNX Runtime 未加载到主进程 |

内存单位为 MiB（1024²），工作集包含可共享的运行库页；不是任务管理器默认列的精确对应。主程序数字来自独立的合成输入验证模式，未显示工作台、恢复用户贴图或录屏；不是所有使用场景的固定启动值。大图会有明显的临时峰值，这是完整模型的实际资源成本；峰值属于子进程，正常完成或取消后退出。电脑配置、图片大小及同时运行的程序会影响速度。

## 验证与交付

- 原有原生回归：19 项通过。
- OCR 回归：8 项通过，覆盖效果对照、文字体系、透明/旋转/多行/空白图片、冷启动、取消/失败清理、中文路径、大图分块和识别窗口。
- 录屏回归：10 项通过。本轮实际桌面纯色测试画面能被采集，区域/全屏/第二显示器的成片解码检查均通过，边框与控制条对应位置没有进入测试视频。v0.5.1 当时的桌面环境跳过情况保留在旧更新记录中；本轮结果仅适用于这台测试电脑的采集路径。
- 便携包：清除 SDK/Python 路径后，使用 Windows 平台运行 6 项部署检查通过；包内主程序连续 OCR 的内存验证通过，3 次后约 29.3 MiB，无残留识别进程。测试运行库仅放在独立验证目录，没有进入发布包。

目录：`dist/FloatShot-Native-0.5.2/`。主程序为 `FloatShotNative.exe`；不要只复制一个 EXE，要保留整个目录，尤其是 `ocr/` 和运行库。旧版 v0.5.1 与旧 Python 发布包保留。更新时先用旧版托盘菜单退出旧版，以释放 F1/F3 快捷键，然后启动新版。

构建依赖可通过 `native/setup-sdk.ps1` 一并准备，也可单独运行 `native/setup-ocr-sdk.ps1`。需要 Visual Studio C++ 桌面工具、CMake 和 Windows SDK，不需要 Python、CUDA 或显卡。
