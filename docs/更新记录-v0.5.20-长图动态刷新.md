# picut v0.5.20 · 长图动态刷新

用户观察到微信的滚动截图会更新之前已拼长图中的表情。本版按这个可见行为调整；没有取得微信的内部实现，不能推断其实际算法。

v0.5.19 已经会刷新用于匹配的上一帧，但通常只向最终长图追加新内容，只有接缝处可能替换旧像素。本版将已拼结果也作为可更新的画布。

## 行为

- 页面不滚动、表情仍播放时，刷新已拼长图中当前可完整看到的动态区域，高度不变。
- 滚动后回到已截位置，也更新该位置的动态内容，不重复追加。超出已截范围才向上或向下补新内容。
- 预览和最终导出共用更新后的像素。预览刷新独立于高度变化，不把动画刷新当作滚动，也不延迟自动模式的停止判断。
- 记住检测到的动态矩形在长图中的坐标，并随向上补图调整位置；后续匹配结合这些位置，仍需要矩形以外的稳定文字和边缘确认位移。
- 已知动态块只有一部分可见时，保留已有画面，等完整可见后再刷新，减少上下两部分来自不同动画帧。离开视口的区域保留最近一次已捕获的状态。

原始像素继续存入临时条带。刷新直接映射受影响的条带并改写对应矩形，再生成独立拥有像素的缩略图；静止刷新不创建新条带，也不反复拼出整张长图。运行依赖不变。

## 验证与范围

三项新增行为检查在旧实现上失败，修改后通过：静止时更新多个表情、回看旧区域后更新、保留半可见表情的完整旧帧。另测小尺寸图片连续刷新 60 次后输出和预览逐像素一致、条带数量不增长、重复帧不产生内容修订；真实会话中即使尺寸不变，预览仍收到重绘，导出与最新帧一致。

保留原有的上下滚动、接缝、静态内容逐像素比对、无重叠跳转和重复气泡误拼接检查。Windows 实桌面合成聊天测试增加最终动画帧检查，验证预览更新会进入导出，采集的都是合成测试窗口，不读取个人聊天记录。

完整回归 110 项通过、0 失败，3 项实桌面用例在离屏平台跳过；另在 Windows 桌面验证 5 项通过（含初始化与清理）、0 失败、0 跳过。1280×900 普通合成图连续 40 步的匹配、预览和条带写入中位约 9.0ms，P95 约 11.0ms，不含抓屏和最终导出，不代表复杂动画页面耗时。

回归和发布报告位于 `.test-artifacts/native-v0.5.20-tests.txt`、`native-v0.5.20-scroll-windows-tests.txt` 和 `native-v0.5.20-release-report.json`。这些检查验证了本次更新行为，不代表在所有聊天软件中的拼接成功率。动画区域过大、无法识别完整边界、缺少稳定重叠或一次跳过整屏时仍可能失败。

## 使用与回滚

安装包 `dist/picut-0.5.20-setup-x64.exe`，便携包 `dist/picut-0.5.20-win-x64.zip`。退出旧版后运行新版；设置和历史目录不变。v0.5.19 程序和安装包保留，源码标签 `v0.5.19-animated-scroll`；本版标签为 `v0.5.20-live-scroll`。
