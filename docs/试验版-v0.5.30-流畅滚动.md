# picut v0.5.30：修复回到已截区域时重复补到顶部

本版针对“往回滚到最初截图的位置，内容却被当成新的一段补到顶部”的问题，继续在 `codex/scroll-performance-trial` 分支开发。v0.5.29 的程序、安装包和 Git 标签保留。

## 问题与修改

聊天记录包含重复表情、图片和文字时，旧逻辑可能把一小段完全相同的重叠，排在“整屏能够对应，但有少量动态变化”的历史位置之前。快速判断还把未截到的新增像素作为位置证据，可能提前跳过正确历史位置。另一个问题是：整数像素画面有时会沿用光流估计的小数相位，影响后续定位。

本版修改如下：

- 定位依据限定在已经确认的重叠范围，要求多个分散且具有区分度的已知行共同支持位置；新增内容本身不作为历史位置的证据。
- 向上补到历史范围之外前，额外核对最初截图的完整位置；有冲突的位置保留歧义检查，不再仅凭短重叠的零误差决定补图。
- 已确认的历史位置按证据优先级选择，避免原本已找到正确位置，最后却因为候选误差并列而选中另一个位置。
- 优先检查整数像素相位；连续跟踪的快速路径只在已经建立可靠坐标、未丢失跟踪且有足够重叠时使用，不用于跳过新增顶部的历史检查。

操作结果应为：回到已截区域时只移动预览中的视口提示，保持长图长度和已确认内容；确实向上滚出了已截范围，才向顶部增加内容。无法确定位置时保留已确认结果，等待能够重新定位的画面。

## 验证

本机 Windows 11、Ryzen 5 9500F、32GB RAM 验证：

- 加入重复聊天、返回原始位置并伴随局部重绘的回归用例，检查位置回到零、成图尺寸和内容版本均不变化。
- 使用本次用户提供的 650×5804px 图片，分别以 480、720、960px 视口进行连续滚动和往返回放。每个被接收的位置及输出像素均与参考内容核对，回访期间不得增加长图内容。
- 完整拼接离线回归 37 项通过；2 项真实桌面采集测试另行通过。基础截图、标注、贴图和录屏回归 120 项通过，5 项桌面交互用例另行通过。真实桌面测试的最终静态成图与参考图片逐像素一致。覆盖真正向上补图、动态加载圈、悬停变色、不同数字的重复消息、分数像素滚动及浏览器图片。
- 1000×800 选区、77 次更新的长图回放，最终高度 30800px，原始像素完整一致。本轮单帧处理 P95 为 10.722ms、P99 为 12.012ms，测试进程工作集增量约 23.00MiB。该数字仅为离线引擎测试，不能替代真实桌面预览或整进程峰值内存。

测试记录保存在 `.test-artifacts/native-v0.5.30-*`。用户参考图片只从本机临时文件读取，没有加入 Git 或安装包。

## 安装与回退

- 安装包：`dist/picut-0.5.30-scroll-trial-setup-x64.exe`。
- 便携包：`dist/picut-0.5.30-scroll-trial-win-x64.zip`。
- 工作区启动：`run-scroll-performance-trial.ps1`，静默进入托盘。
- 安装或启动前，先从托盘退出正在运行的试验版，释放文件和全局热键。安装器不主动结束旧进程。
- 沿用 v0.5.29 的安装身份、安装目录 `%LOCALAPPDATA%/Programs/picut-scroll-performance-trial` 和数据目录 `%LOCALAPPDATA%/FloatShot/FloatShotNative-ScrollPerformanceTrial`，不清空设置、历史或贴图。
- 回退 v0.5.29：退出本版，启动 `dist/picut-0.5.29-scroll-trial/picut.exe` 或使用保留的 v0.5.29 安装包。
- Astra v0.5.27 仍由 `run-scroll-trial.ps1` 启动，正式 v0.5.26 仍由 `run.ps1` 启动，两者数据目录与本版独立。

6400 万像素、100000px 高度等安全上限及其他适用范围沿用 v0.5.29，详见 [v0.5.29 试验版说明](试验版-v0.5.29-流畅滚动.md)。本轮未进行 Windows 10 实机验证。
