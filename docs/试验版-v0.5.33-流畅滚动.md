# picut v0.5.33：接续发生局部变化的边界卡片

本版处理实际长图中三张图片由加载状态变为失败状态、文件卡片内容也发生变化时，继续向上滚动无法拼接的问题。继续使用现有流畅性试验版的安装身份和数据目录；v0.5.32 和此前版本保留。

## 原因与行为

用两张原图复现后，历史索引已经找到正确的 -230px 位移，但后续整段重叠检查拒绝了它：原长图边缘的文件列表和三张加载卡片发生变化，卡片高度也变化了。下方连续的消息文字位置仍一致，只有少量像素存在不超过 7 级的颜色差异。这个样本不是长度上限或采集队列溢出。

普通匹配失败时，新路径先在边界变化之后寻找至少 96px 连续稳定、具有纹理的内容，并要求其中多个稀有行特征支持同一个历史坐标。白色背景本身不能作为定位证据。随后再核验剩余重叠内容，允许其中有界的局部重绘；边界变化段的像素差异比例不能超过五分之一，长度最多半个选区高度且不超过 512px。确认后刷新这段接缝，追加真正超出历史范围的内容，其余历史像素保持原样。

局部变化的外接范围改为按实际变化像素计算，避免一个跨过网格线的小光标或动画，被网格扩大为大块变化。仍保留固定栏、滚动条、重复内容歧义、大块变化和未知坐标保护。此前的边界空白补绘路径保持可用。

该机制处理受限的边界内容更新，不保证任意页面重排都能连续拼接。稳定参照不足或变化范围过大时仍会拒绝匹配，保留已确认的内容。普通成功帧使用原有快速路径。

## 样本与验证

原长图为 808×15205px，第二张手动框选为 861×633px。样本回放先将第二张图横向裁去左侧 25px，与原选区对齐；这只用于离线核验，不为运行选区加入自动水平移动。先回放生成完整原长图，再接入新画面，结果为 808×15435px：顶部新增 230px，更新原边界 229px，完整保留后方消息。最终图与独立构造的参考图逐像素核对，并检查回访不重复追加。截图中的鼠标指针没有被写入后方已确认消息。

另有向上、向下边界重绘用例，以及大块纹理变化、稳定参照丢失、稳定带之后的内容冲突等拒绝用例。旧版真实图片、不等距回滚、错开停止位置、重复聊天、局部动画和浏览器回放继续纳入回归。用户原图仅保存在本机忽略的测试目录，不进入 Git 或安装包。

测试记录与实际合成图位于 `.test-artifacts/native-v0.5.33-*`；完整实际结果为 `.test-artifacts/native-v0.5.33-scroll-v2/repainted-boundary-long.png`。

本机结果：拼接离线回归 **62 通过、0 失败**，两个桌面采集用例另行通过；基础功能回归 **120 通过、0 失败**，五个桌面业务场景另行通过。1000×800 选区的 77 次更新均接入，生成 30800px 高的静态结果并逐像素核对；离线处理 P95 **13.416ms**、P99 **14.318ms**，测试进程工作集增量约 **23.64MiB**。后段 P95 没有随图长增长而上升；8ms 的离线 P95 目标尚未达到。该数字不包含桌面采集、预览呈现和最终导出峰值。独立桌面生产者场景的 10 次位置变化全部追踪到，预览 P95 约 **90ms**，该受控场景不能代表任意页面动画或任意机器表现。

## 安装与回退

- 安装包：`dist/picut-0.5.33-scroll-trial-setup-x64.exe`。
- 便携包：`dist/picut-0.5.33-scroll-trial-win-x64.zip`。
- 入口：`run-scroll-performance-trial.ps1`，默认进入托盘。
- 更新前先从托盘退出当前试验版，安装器不主动结束旧进程。
- 沿用 `%LOCALAPPDATA%/Programs/picut-scroll-performance-trial` 和 `%LOCALAPPDATA%/FloatShot/FloatShotNative-ScrollPerformanceTrial`，保留设置、历史与贴图。
- 回退时退出新版，启动 `dist/picut-0.5.32-scroll-trial/picut.exe` 或使用保留的 v0.5.32 安装包。
- 正式版 v0.5.26 和 Astra v0.5.27 的程序、入口、配置目录继续独立保留。

测试机器为 Windows 11、Ryzen 5 9500F、32GB RAM，未进行 Windows 10 实机验证。其余范围与安全上限沿用 [v0.5.29 说明](试验版-v0.5.29-流畅滚动.md)。
